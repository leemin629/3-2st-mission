# 📈 Stock Insight AI

> 주가 데이터를 분석하고, AI와 대화하며 인사이트를 얻는 웹 애플리케이션

저장된 주가 데이터를 실시간으로 요약·시각화하고, 그 요약 정보를 AI에게 주입하여  
**데이터 기반의 정확한 답변**을 제공합니다.

---

## ✨ 주요 기능

- 📊 **주가 요약 & 차트** — 평균/최고/최저/등락률/트렌드 자동 계산 + 라인 차트
- 🤖 **데이터 기반 AI 채팅** — 요약 정보를 프롬프트에 주입한 Gemini 답변
- 🗂️ **데이터 관리(CRUD)** — 추가/조회/수정(메모 인라인 편집)/삭제
- 📜 **대화 기록** — 대화 자동 저장 + 목록 조회 + 삭제
- 🌙 **다크 모드** — 라이트/다크 토글, 설정 자동 저장
- 🖱️ **팝업 드래그** — 채팅/데이터/대화 창을 자유롭게 이동

지원 종목: `NVDA` `AAPL` `TSLA` `MSFT` `GOOGL`

## 💻 로컬 실행 방법

### 1. 저장소 클론

```bash
git clone https://github.com/leemin629/3-2st-mission
cd 3-2st-mission/backend
```

### 2. 가상환경 생성 & 활성화

```bash
python -m venv venv
```

#### Windows

```bash
venv\Scripts\activate
```

#### Mac/Linux

```bash
source venv/bin/activate
```

### 3. 패키지 설치

```bash
pip install -r requirements.txt
```

### 4. 환경 변수 설정

`backend` 폴더 또는 실행 환경에 `.env` 파일을 생성하고 아래 값을 설정합니다.

```env
# Google Gemini API 키
GEMINI_API_KEY=your_gemini_api_key

# Firebase 서비스 계정 키
FIREBASE_CREDENTIALS=your_firebase_credentials
```

> ⚠️ API 키와 Firebase 인증 정보는 절대 코드에 직접 작성하지 않습니다.  
> `.env` 파일은 반드시 `.gitignore`에 포함하여 GitHub에 올라가지 않도록 관리합니다.

### 5. 서버 실행

```bash
py -m uvicorn main:app --reload
```

또는

```bash
python -m uvicorn main:app --reload
```

브라우저에서 아래 주소로 접속합니다.

```text
http://localhost:8000
```

## 🧠 컨텍스트 주입 원리

본 프로젝트는 사용자가 선택한 종목의 저장 데이터를 요약한 뒤, 해당 요약 정보를 AI 프롬프트에 함께 전달합니다.

```text
1. 사용자가 종목을 선택하고 질문 입력
2. 백엔드에서 선택 종목의 요약 데이터 조회
3. 평균가, 최고가, 최저가, 등락률, 트렌드 정보를 생성
4. 생성된 요약 정보를 Gemini 프롬프트에 삽입
5. Gemini API 호출
6. AI 답변 반환
7. 사용자 질문과 AI 답변을 대화 기록으로 저장
```

이 방식으로 AI는 단순한 일반 지식이 아니라,  
**Firestore에 저장된 실제 주가 데이터 요약 정보**를 근거로 답변할 수 있습니다.

---

## ⚠️ 컨텍스트 주입 방식의 한계와 보완

컨텍스트 주입 방식은 AI 답변의 정확도를 높이는 데 도움이 되지만, 다음과 같은 한계가 있습니다.

### 한계

1. **컨텍스트가 길어질수록 토큰 사용량이 증가합니다.**  
   너무 많은 데이터를 프롬프트에 넣으면 비용과 응답 시간이 증가할 수 있습니다.

2. **불필요한 정보가 포함되면 답변 품질이 낮아질 수 있습니다.**  
   질문과 관련 없는 데이터가 많으면 AI가 핵심을 놓칠 수 있습니다.

3. **오래된 데이터가 현재 상황과 맞지 않을 수 있습니다.**  
   저장된 주가 데이터가 최신 시장 상황을 완전히 반영하지 못할 수 있습니다.

4. **AI 응답은 참고용이며 투자 판단을 대신할 수 없습니다.**  
   AI는 요약 데이터를 기반으로 설명하지만, 실제 투자 결정은 사용자의 책임입니다.

### 보완 방법

1. 선택한 종목의 핵심 요약 정보만 프롬프트에 주입합니다.
2. 평균가, 최고가, 최저가, 등락률, 트렌드처럼 질문에 필요한 지표 위주로 전달합니다.
3. 모든 원본 데이터를 넣지 않고 요약된 데이터만 전달하여 토큰 사용량을 줄입니다.
4. 사용자가 보는 차트와 요약 정보를 함께 제공하여 AI 답변을 직접 검증할 수 있게 합니다.

## 🗂️ Firestore 컬렉션 설계

본 프로젝트는 데이터의 목적에 따라 Firestore 컬렉션을 분리하여 사용합니다.

예시 구조는 다음과 같습니다.

| 컬렉션 | 역할 |
|--------|------|
| `stock_data` 또는 데이터 컬렉션 | 종목별 주가 데이터 저장 |
| `conversations` | 사용자와 AI의 대화 기록 저장 |
| `settings` 또는 브라우저 저장소 | 다크 모드 등 사용자 설정 저장 |

### 컬렉션을 분리한 이유

1. **데이터의 성격이 다르기 때문입니다.**  
   주가 데이터와 대화 기록은 저장 목적과 조회 방식이 다릅니다.

2. **조회 성능과 유지보수성을 높이기 위해서입니다.**  
   주가 데이터 조회 API와 대화 기록 조회 API를 분리하면 각 기능을 독립적으로 관리하기 쉽습니다.

3. **기능 확장에 유리합니다.**  
   나중에 종목 데이터, 사용자 정보, 즐겨찾기, 대화 분석 기능이 추가되어도 기존 구조를 크게 바꾸지 않고 확장할 수 있습니다.

4. **데이터 삭제와 수정 범위를 명확히 할 수 있습니다.**  
   예를 들어 대화 기록을 삭제하더라도 주가 데이터에는 영향을 주지 않습니다.

## 💾 대화 저장 시점

사용자와 AI의 대화는 **AI 응답이 생성된 직후** 저장됩니다.

저장되는 주요 정보는 다음과 같습니다.

| 항목 | 설명 |
|------|------|
| 사용자 질문 | 사용자가 입력한 메시지 |
| AI 응답 | Gemini가 생성한 답변 |
| 선택 종목 | 사용자가 질문한 종목 |
| 생성 시간 | 대화가 생성된 시간 |

### 이 시점에 저장하는 이유

1. **질문과 답변을 한 쌍으로 보관하기 위해서입니다.**  
   사용자 질문만 저장되거나 AI 답변만 저장되면 대화 맥락을 확인하기 어렵습니다.

2. **새로고침 후에도 이전 대화를 확인할 수 있습니다.**  
   대화 기록을 Firestore에 저장하여 사용자가 다시 접속해도 목록을 불러올 수 있습니다.

3. **이후 대화 맥락 구성에 활용할 수 있습니다.**  
   최근 대화 기록을 기반으로 사용자의 관심 종목이나 질문 흐름을 파악할 수 있습니다.

4. **데이터 손실을 줄일 수 있습니다.**  
   AI 응답이 완료된 시점에 바로 저장하여 사용자가 화면을 닫더라도 기록이 남도록 합니다.

## 🧊 콜드 스타트 대응

백엔드는 Render 무료 티어를 사용하기 때문에 일정 시간 요청이 없으면 서버가 sleep 상태가 될 수 있습니다.  
이 상태에서 첫 요청이 들어오면 서버가 다시 시작되면서 응답이 느려지는 **콜드 스타트**가 발생할 수 있습니다.

### 발생 가능한 현상

- 첫 접속 시 페이지나 API 응답이 늦게 도착할 수 있습니다.
- Swagger UI 접속 시 처음에는 로딩이 오래 걸릴 수 있습니다.
- 첫 채팅 요청이 평소보다 느릴 수 있습니다.

### 완화 방법

1. **사용자에게 첫 요청 지연 가능성을 README에 안내합니다.**
   - 백엔드 무료 티어 특성상 첫 요청이 느릴 수 있음을 명시했습니다.

2. **가벼운 API를 먼저 호출하여 서버를 깨울 수 있습니다.**
   - 프론트엔드 접속 시 백엔드 기본 URL 또는 Swagger UI에 먼저 접근하면 이후 요청이 빨라질 수 있습니다.

3. **운영 환경에서는 주기적인 health check를 사용할 수 있습니다.**
   - 일정 주기로 서버에 요청을 보내 sleep 상태 진입을 줄일 수 있습니다.
   - 예: `/docs`, `/api/data`, 또는 별도의 `/health` 엔드포인트 사용

4. **무거운 초기 작업을 최소화합니다.**
   - 서버 시작 시 모든 데이터를 한 번에 불러오기보다, 실제 API 요청이 들어왔을 때 필요한 데이터만 조회하도록 구성합니다.

## 🔐 보안 관리

본 프로젝트는 API 키와 Firebase 인증 정보를 안전하게 관리하기 위해 다음 원칙을 적용합니다.

3. `.env`와 Firebase 인증 키 파일은 `.gitignore`에 포함합니다.

5. 이미 노출된 키는 Firebase 콘솔에서 폐기하고 새 키를 발급받습니다.

